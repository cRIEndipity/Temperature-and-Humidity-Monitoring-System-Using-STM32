# Temperature-and-Humidity-Monitoring-System-Using-STM32
This introduced the practical process of building a Temperature and Humidity Sensing System using an STM32 microcontroller on the RT-Thread RT-Spark Development Board. Temperature and humidity sensors are widely used in real-life applications such as weather stations, smart homes, agricultural monitoring systems, and industrial environments. In this activity, the onboard AHT21 sensor was used to measure environmental conditions, while the integrated LCD served as the output device to display the readings in real time.

The main objective of the laboratory was not simply to obtain temperature and humidity values from the sensor. More importantly, the activity aimed to deepen understanding of how a microcontroller communicates with peripheral devices and how raw sensor data is processed and presented in a meaningful way. Instead of treating the sensor and display as independent components, the system was designed so that hardware and software worked together as a complete embedded application. This approach helped demonstrate how real-world embedded systems operate continuously and reliably.

To achieve this, the STM32 microcontroller was configured to communicate with the AHT21 sensor using the I2C protocol. Through this communication method, the microcontroller was able to request measurements, receive raw digital data, and convert it into human-readable temperature and humidity values. These values were then sent to the LCD, which was driven by the ST7789 controller using the FSMC peripheral. This setup allowed the display to update quickly and smoothly, making the system feel responsive and stable during operation.

During development, the system was first tested using simple static outputs to confirm that the LCD was functioning correctly. Once display functionality was verified, live sensor data was introduced. The program was designed to continuously read the sensor at regular intervals and update the LCD accordingly. This demonstrated how embedded software can dynamically refresh outputs instead of displaying fixed or static information. Observing the values change in response to environmental conditions helped validate both the sensor accuracy and the correctness of the data conversion process.

The laboratory also highlighted the importance of careful testing and debugging in embedded systems development. Several challenges were encountered, such as ensuring proper peripheral initialization, verifying I2C communication stability, and maintaining consistent LCD updates without flickering. These issues required systematic troubleshooting, including checking configuration settings, reviewing datasheets, and testing individual components step by step. Through this process, valuable problem-solving skills were developed.

Overall, this laboratory activity emphasized that embedded systems development involves much more than simply connecting components together. It requires a clear understanding of hardware interfaces, careful software design, and thorough testing to ensure reliable operation. Even with relatively simple components like a temperature and humidity sensor and an LCD display, the activity provided meaningful insight into how complex embedded applications are built. The experience gained from this laboratory serves as a strong foundation for developing more advanced systems in future projects.
